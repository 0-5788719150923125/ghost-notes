# Architecture audit: where a change has to land twice

**Status.** Source audit of the working tree at `86836c8`. The review sampled the last 60 commit subjects, checked the architecture notes and existing gates, and scanned 560 GDScript files for repeated function bodies. The findings below come from tracing selected implementations, including the Python voice host. Runtime impact is attributed to earlier measurements where available. This audit adds no new benchmark.

**Decision.** For new features, the highest-leverage change is to make the card and the running scene consume the same feature instance. Today a scene can play correctly while its authoring controls are missing. For existing playback code, the table’s live-to-bake handoff remains the highest-risk duplication reviewed here.

## Why card integrations keep getting missed

The project has schemas for features that have been declared. It also has independent ways to build the same behavior directly in a scene. Three paths show the gap:

| Feature | What the contract knows | What a scene still does separately |
| --- | --- | --- |
| Camera | Which sorts appear, their fields and defaults | Builds shots and reads individual fields. An unknown, unset field reads as zero. The card gate explicitly supplies the game’s registration, so that check can pass even if production stops registering it. [Values](../src/motion/cameras.gd) · [Card gate](../tests/show/camera_card_check.gd) |
| Show-made sound | A typed `ShowSounds` provider supplies entries to the Sound card | Studio installs its provider in the panel separately from playing its acts. The base provider can return an empty list. Hearing a new sound therefore proves nothing about whether the author can find or change it. [Provider](../src/music/show_sounds.gd) · [Studio adapter](../src/studio/studio_format.gd) |
| Environment | `Surroundings.offers` enumerates fog looks from the registry | Studio assembles fog, rays and air in its own dress method, supplying room bounds and a camera. Another scene can consume only part of the same environment. A complete Dex proves the offers exist; it cannot establish what a mounted scene renders. [Offers](../src/table/surroundings.gd) · [Studio dressing](../src/studio/studio.gd) |

**Pilot the contract on Environment.** Have a participating 3D scene supply its world, bounds, light direction and viewing geometry once. A shared environment implementation takes the saved elements, applies their registered behavior and handles live changes. Each new fog look then reaches every participating room by default. Keeping any genuine rendering limitation explicit lets the card explain it. For Cameras, apply the same ownership rule to registered shot instances and inherit related field groups such as sway and sway speed together. For Sounds, have playback and the card resolve each author-editable show sound through the same provider and stable key.

**Make omissions fail at the normal entry point.** Mount a small production scene, add each registered fog look through the card, save and reopen, and inspect the resulting effect with a non-default field. Include a control that skips fog application and must fail. For a show sound, change its level on the card and check the level used by playback. For a camera, activate the actual shot and check that an edit changes its sampled pose. A typed provider helps once it is on this required path. A second manifest of features to remember would reproduce the oversight.

## Parity between agents and authors

Studio placement already shows how this can work. The Props card and the refine agent both get their fields from `StudioSet.PLACE_FIELDS`. A card edit and an agent move both call `StudioFormat.set_place`, so they share bounds, persistence and undo history. The agent can inspect measured geometry while the author moves a control. Each sees the placement the other left behind. [Card and refine bindings](../src/studio/studio_props.gd) · [Placement operation](../src/studio/studio_format.gd)

**Make parity a condition of publishing an authoring operation.** A feature declares its owning card, readable state, editable fields and operations once. Use those declarations to build the card controls and agent tool schema, and route both through the same implementation. For ordinary fields, infer a widget from the declared type, range or choices using `SchemaForm`. For a compound operation such as arranging several props, a named card action can preview and apply the same proposal the agent makes. When an operation is intentionally available on only one side, record which side and why. [Existing form controls](../src/ui/schema_form.gd)

Enforce this against the **actual tools and controls**. Fail the gate when an agent tool that changes the note has no authoring operation, or an operation lacks either binding without an explicit exception. Pilot it on fog: set density through the tool, read it on the card, reset it there, then read the effective default through the tool. Reopen the note and check the mounted fog. Removing either binding must fail the test. This catches missing controls, stale readback and edits that save correctly but never reach the scene.

## Playback and export must show the same composition

The Studio flip screen was visible during playback and missing in the exported video. It takes two dependent render passes: the prop’s lens draws the room into a viewport, a second viewport mirrors that picture and overlays the recording marks, and the main shot sees their texture on the prop. The Studio geometry gate checks what falls within the lens angle. That can pass with a blank screen in the movie. The working tree also remounts the screen after a stop; whether that resolves this export is unverified. [Screen composition](../src/studio/studio_screen.gd) · [Screen lifecycle](../src/studio/studio.gd) · [Geometry gate](../tests/studio/studio_script_check.gd)

**Contract.** At the same authored time, with the same saved take, camera and framing, the viewer and exporter consume the same composed stage. A secondary view sampled by a visible surface is a required input to that frame. Have the component that creates the surface own its producer and binding across mount, rebuild and restart. Export must wait for required views to produce a frame before capture and surface a render error if a required binding cannot be established. Output resolution and compression can vary while the authored content stays present.

**Acceptance gate.** Use a short Studio fixture with a distinctive moving target visible only to the prop’s lens. Capture the viewer stage and run the production export on the same take. Decode the final video at two matching times and inspect the projected screen face for the target in its two positions. Use a local color/position tolerance for compression. Blanking the lens feed while leaving REC and the meters alive must fail, as must freezing the first frame. Repeat after stop/play to cover rebinding. This tests the small region a whole-frame similarity score could overlook. [Movie Maker and encoding path](../src/export/exporter.gd)

## Make ordinary medium variants data

Extend `Medium.make`, the factory the Director already calls, to assemble registered parts from a medium definition. Today a registry row names a script, and that script gets to decide how much of the framework to use. Auto illustrates the easy end: its subclass adds no behavior to Full, and its row already describes its settings policy. Studio illustrates the payoff: a definition could select the set, prop roles, head camera and contact-sound behavior. The head trajectory and microphone contact calculations still need executable implementations. [Medium factory](../src/media/medium.gd) · [Auto](../src/media/auto.gd) · [Studio](../src/studio/studio.gd)

Make each part own its defaults, field schema and runtime behavior. The assembled medium owns the mounted instances and their lifetime. Cards edit the same settings those instances consume. A format can override a default or supply room geometry without repeating a list of supported fog kinds or camera fields. Validate unknown part names, missing inputs and invalid overrides when loading the definition.

Prove this on the Environment slice of Studio and Dispatch. Keep their existing format keys and note blocks, supply each room’s bounds and light anchors as inputs, and move the shared dressing lifecycle into one part. The proof is a third room assembled from existing parts, with a working Environment card and live fog edits, using only a definition. Migrate camera and sound the same way once that works. Leave Table’s simulation behind its current interface until a composition actually needs it.

## Findings in priority order

1. **Table playback and physics have a fragile handoff.** `TablePhysics._make_twin` assigns more than twenty fields to a second `TableWork`, including private pose, movement and writing state. `rebind` separately refreshes the act-dependent subset. Someone adding a motion feature must know which values are shared, which are copied for the worker, and which become stale after an edit. The earlier bake audit traced visible placement failures to disagreement about where things rest. Give `TableWork` ownership of the node-free plan data a bake consumes. Start with the act-dependent fields common to construction and rebind. Keep mutable solver state private to the worker. The acceptance check is a changed act producing the same poses in a fresh bake and an incremental rebake, including a prop at rest between spoken cues. [Handoff](../src/table/table_physics.gd) · [Measured failures and probe](framework_audit.md)

2. **Prop selection still gets rebuilt around a shared Props card.** Five classes implement the same thumbnail-request loop (`_asked`): DeskProps, DispatchProps, StudioProps, LibraryProps and MakeShelf. The more consequential duplication is in Dispatch and Studio. Both resolve the role, load a refined version, check its fit, detect an unchanged choice and persist the new one. Even the feedback has diverged: Studio reports missing features, while Dispatch lists the role’s faces. Put the thumbnail operation on the existing `PropSection` and give both formats one role-choice operation returning the specific fit result. Leave Dispatch’s roots preview and Studio’s placement controls with their owners. A refined microphone missing a required feature should leave the choice intact and explain what is missing. [Dispatch](../src/dispatch/dispatch_props.gd) · [Studio](../src/studio/studio_props.gd) · [Shared section](../src/ui/prop_section.gd)

3. **Three word matchers can disagree about the same take.** Book, Tablet and ReadingFollower each maintain a cursor, search a window and retain the remainder of a split word. Tablet requires two characters for a prefix match. ReadingFollower also accepts one at the current cursor. This can put a highlight and an act on different words. Extract the matcher beneath all three, retaining each caller’s index mapping and seek behavior. First characterize one-letter fragments, a repeated word after a seek and a take that restarts. That makes deliberate differences visible before choosing one rule. [Book](../src/media/book.gd) · [Tablet](../src/media/tablet.gd) · [ReadingFollower](../src/media/reading_follower.gd)

4. **Sound has two smaller, concrete maintenance costs.** Table and Dispatch carry identical bodies for `_sine`, `_burst`, `_drop_voice` and `_drop_burst`, alongside matching arrays for active sounds. Extract that synthesis state on the next change to either renderer and compare fixed-seed samples. Voice has a different issue: Godot’s sentence seam and Piper’s punctuation both implement the pause curve, including the exponent 0.69897. They run in separate processes. A shared table of input scales, dwell times and expected rests would let both existing test suites enforce the same behavior cheaply. [Table sounds](../src/table/work_sounds.gd) · [Dispatch sounds](../src/dispatch/dispatch_sounds.gd) · [Delivery](../src/voice/delivery.gd) · [Piper](../hosts/voice/backends/piper.py)

## Directors and layouts

**Direction already has a useful division of labor.** The show Director chooses scene cuts. The Camera card and `CameraFollow` share camera settings and movement. A table game knows when dice land, Studio knows where the microphone is, and Book knows which word must stay visible. Pop-up Book inherits Book’s turn and reading behavior. Preserve that arrangement. For future production formats, the pressure point is upstream: Studio’s choice to write acts into narration affects step enumeration, dependency tracking and freshness in `TableEpisode`. When a second format needs that choice, give a passage one prerequisite description used by all three. [Camera contract](camera.md) · [Episode steps](../src/table_show/table_episode.gd)

**A single layout controller would buy little today.** Table checks authored card footprints and reports violations. Dispatch scores candidate prop poses against clearance, reach and visibility, then picks one. Studio applies a centimeter offset to a role’s authored transform and already uses one field definition for the editor and sanitizer. A shared authoring primitive makes sense when another room needs that offset. For now, the repeatable operation across these sets is choosing a prop for a role. Fixing that first benefits the author without changing saved coordinates, seeded layouts or how each camera sees the set. [Table positions](../src/table/table_positions.gd) · [Dispatch packing](../src/dispatch/dispatch_set.gd) · [Studio placement](../src/studio/studio_set.gd)

## Real-time playback and automatic baking

Table physics already bakes on a worker to a 20-second target while playing. Pausing expands that target toward the remaining show, capped at 30 minutes. ReadingStream also makes voice ahead while paused. Studio prepares act motion and sound on workers. A full buffer means those results are ready. Applying poses, updating UI, submitting geometry and drawing each view still take frame time. [Table playback](../src/table/table.gd) · [Physics limits](../src/table/table_physics.gd) · [Voice buffering](../src/reading/reading_stream.gd)

**Measure the hitches with a warm buffer first.** A local Studio session log shows the governor reporting 25–38 ms of app-thread time on expensive frames and 2–7 ms as it recovers. These are smoothed readings at governor transitions. They establish CPU pressure without isolating a function. Studio calls `_ensure_doc` on every advance, sanitizing and serializing environment settings even on an unchanged frame. It also serializes takes and marks in `_making_of` to decide whether preparation is current. Time those checks, pose application, sound updates and GPU stage time on the same passage, first cold and then after pausing until ready. Compare p95/p99 frame intervals and seconds of buffer remaining at each hitch. The previous table probe shows why presentation and GPU time need separate measurements. [Studio frame loop](../src/studio/studio.gd) · [Corrected table measurements](table_playback_investigation.md)

**Extend the existing ready-ahead mechanism where the measurement pays for it.** A deterministic part can prepare bounded time ranges off-thread, report the last contiguous ready time, and sample them at playback. Prioritize the playhead after a seek, cap memory and worker concurrency, and discard stale results from the first affected cue when an edit or new word timing changes the plan. Pausing buys compute time. An unchanged settings block is cheaper to process once on edit, and a GPU-bound view still needs rendering work even with every pose cached.
